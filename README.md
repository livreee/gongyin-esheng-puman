# 工银e生 · 21天扑满计划

面向青年用户的理财知识与储蓄习惯互动 Demo。项目将生活目标、21 天剧情任务、像素宠物养成、答题画像和时序行为分析结合起来，帮助用户理解资金用途、期限与风险，为自主了解工商银行正式理财服务建立认知基础。对工行的核心价值是承接青年用户从财商练习到正式服务了解、评估与自主选择的旅程；活跃和留存是这一承接过程的支持指标。

**当前网页主版本是 `web/index.html`，App WebView 入口是 `web/h5.html`，完整运行入口是 `python web/server.py`。** 本文统一介绍主版本、H5 适配、历史原型、素材、计划书、技术实现和交付方法。`21day-wealth-script/` 为历史静态版本，新功能以 `web/` 为准。

本项目为比赛演示原型。页面中的存钱金额、金币、i 豆和队友进度为演示数据，不连接真实银行账户，不执行转账、扣款或投资交易；页面出现的“存入账户”等描述不代表实际资金到账。

对工行的服务承接路径：生活目标练习 → 完成21天并回顾 → 用户自主进入工行官方渠道 → 正式身份核验、独立授权与适当性流程 → 阅读产品文件后决定。目标只用于选择教育内容，打卡、时序状态与结局均不用于风险评级或推荐具体产品。试点应分别统计完赛、官方入口点击、经授权核验的正式服务办理与后续留存，不把模拟金额计入AUM。

四题生活偏好问卷仍用于原有五类目标匹配；养老线和自定义线由用户自主选择。新增线路放在原有标识之后，保留旧题目索引、答题奖励和存档。主版本与H5共用更新内容，项目交付文件夹同步代码；本轮不修改任何计划书。

验证方式：`python -m unittest discover -s web -p "test_*.py"` 检查后端；`node web/test_story_ui.cjs` 使用隔离数据库和本地模拟模型，验证养老线、旧存档、四类结局、打卡状态的隐私边界、迟到响应与离线回退，并检查320/390/768像素视口。浏览器脚本支持 `PLAYWRIGHT_PATH`、`BROWSER_PATH` 和 `PYTHON` 环境变量。

## 1. 快速运行

准备 Python 3.10 或以上版本（推荐 3.11+）和现代浏览器。主版本不需要安装第三方 Python 包，不需要 Node.js 或前端构建工具。

解压项目，在包含本 README 的目录打开终端：

```powershell
python --version
python web/server.py
```

访问 [本机主页面](http://127.0.0.1:8000/index.html)。终端保持运行，结束时按 `Ctrl+C`。首次运行会自动创建 `web/puman.sqlite3` 数据库。

面向 App WebView 的独立入口为 [本机 H5 页面](http://127.0.0.1:8000/h5.html)。它与主页面共用产品功能和后端，但会去掉桌面端手机外框，并适配刘海屏、状态栏和底部手势区。

建议演示顺序：

1. 点击“开始我的 21 天”，完成四道生活偏好题。
2. 查看财富画像、建议习惯及“看看答题依据”，选择一条剧情线。
3. 完成今日剧情、存钱挑战或每日理财一问，查看攒钱进度与“我的参与节奏”。
4. 切换日历、小队、徽章与纪念品页面，体验宠物旅行和阶段成长。
5. 需要比较不同画像时，返回选择页点击“重新测一测”；已经完成的旅程任务会保留。

也可直接双击 `web/index.html` 体验本地模式：进度保存在浏览器 `localStorage`，答题后会生成基础分析。真实 AI 生成、服务端存档和时序行为推断需要启动后端。字体使用外部样式链接，断网时会使用浏览器的备用字体。

### H5 与 App WebView 对接

`web/h5.html` 会进入 `index.html?mode=h5`，普通网页入口不受影响。H5 模式使用 `viewport-fit=cover`、动态视口高度和四边安全区变量，底部导航、小猪、音乐按钮及提示不会落入系统手势区。

页面公开只读桥接对象 `window.PumanH5`，并兼容 `window.ICBCAppBridge.postMessage`、iOS `window.webkit.messageHandlers.puman.postMessage` 和 `window.ReactNativeWebView.postMessage`。页面向宿主发送以下 JSON 消息：

| 消息 | 用途 |
| --- | --- |
| `puman.ready` | H5 初始化完成，附当前内部路由 |
| `puman.route` | 页面内部路由发生变化 |
| `puman.close` | 位于入口页时请求宿主关闭 WebView |
| `puman.openOfficialContent` | 请求宿主打开已审核的工行 App 内容页 |

宿主可以调用 `window.PumanH5Receive({source:'icbc-app',type:'puman.back'})` 触发返回，也可以发送 `puman.safeArea`，在 `detail` 中提供 0—120 范围内的 `top/right/bottom/left` 像素值。真实工行 App 的桥接名称、登录换票、内部路由和签名规则尚未提供，因此当前桥接不接收登录凭证，也不会把模拟用户标识当成银行身份。取得行内接入规范后，应由原生端与后端完成一次性授权码换票，不能把长期令牌放入 URL、`localStorage` 或 JS 消息日志。

### GitHub Pages + Render 部署

GitHub Pages 只运行静态页面，Python API 由 Render Web Service 运行。本项目后端地址为 [Render 服务](https://gongyin-esheng-puman.onrender.com)，`web/config.js` 已配置此公开网址；配置文件中没有真实密钥。[GitHub Pages](https://livreee.github.io/gongyin-esheng-puman/) 通过该地址调用 API。

如需重新部署或部署自己的副本，可使用仓库中的 `render.yaml`，按以下步骤操作：

1. 确认部署文件已提交至 [项目仓库](https://github.com/livreee/gongyin-esheng-puman) 的 `main` 分支。
2. 打开 [从本仓库创建 Render 服务](https://render.com/deploy?repo=https://github.com/livreee/gongyin-esheng-puman)，登录 Render，授权访问该仓库，按 `render.yaml` 创建 Blueprint。也可在 Render 使用 **New → Blueprint** 选择该仓库。
3. 要启用 DeepSeek，在 Render 服务的 **Environment → Add Environment Variable** 中添加 `LLM_API_KEY`，保存并重新部署。它用于后端调用模型，不应填写到 GitHub 源码、前端配置或 README。可以先不添加密钥来验证连接；未配置时自动使用规则画像。本机 Windows 加密配置不会自动上传到 Render。
4. 等待服务显示 **Live**，复制 Render 分配的实际 HTTPS 地址。先访问 `实际地址/api/health`，应返回 `ok: true`；访问 `实际地址/` 即可使用同源完整版本。`/api/ai/status` 中的 `configured` 仅表示配置齐全，需要实际生成一次画像才能确认模型调用成功。
5. 在 GitHub 编辑 **`web/config.js`**，将 `apiBaseUrl` 更新为上一步的实际地址，例如 `https://你的实际服务名.onrender.com`，不要追加 `/api`、`/index.html` 或仓库路径。提交至 `main`。此文件只存公开后端网址，不能放任何密钥。
6. GitHub **Settings → Pages** 保持从 `main` 分支的根目录发布。等待 Pages 部署完成后打开 [当前网页](https://livreee.github.io/gongyin-esheng-puman/)，根入口会跳转到 `web/` 主版本。页面应显示“后端已连接”，完成任务后可保存进度、查询参与节奏，并在配置有效时生成 AI 画像。

Render 默认自动部署所连接分支的后续提交，提交前应运行本文的本地回归测试。若使用 Fork，需将 `render.yaml` 中的 `ALLOWED_ORIGINS` 改为自己的 Pages 来源，例如 `https://你的用户名.github.io`，不含仓库路径。CORS 以域名来源区分，无法只允许同一 Pages 域名下的某一个仓库；它也不能代替用户身份认证。

默认 Blueprint 使用免费实例，不会配置付费磁盘。免费服务空闲后会休眠，首次访问需要等待唤醒；其 SQLite 位于临时磁盘，**重启、重新部署或休眠后可能丢失服务端存档与行为记录**。浏览器已有本地进度仍可保留，但不能恢复完整的历史行为事件。需要稳定保留数据时，在 Render 升级为支持持久磁盘的付费实例，挂载路径设为 `/var/data`，并将 `DB_PATH` 改为 `/var/data/puman.sqlite3`；同时更新 `render.yaml` 中的计划、磁盘及变量配置，避免以后同步 Blueprint 时覆盖设置。只改 `DB_PATH` 而未挂载磁盘不具备持久性。SQLite 版本保持单实例运行。

本方案沿用比赛原型的 Python HTTP 服务和匿名用户标识，适合小规模演示。公开 AI 接口尚未提供正式登录鉴权与调用额度控制，填写真实模型密钥前应在供应商侧设置用量预算；正式运营前需完成文末所列的上线改造。

## 2. 产品内容与体验

### 六条预设剧情线 + 一条自定义线

| 标识 | 剧情线 | 生活目标 | 场景变化 |
| --- | --- | --- | --- |
| `home` | 我的小家 | 第一笔装修基金 | 从毛坯房到温馨小家 |
| `baby` | 宝贝计划 | 第一笔育儿基金 | 从空房间到布置好的婴儿房 |
| `travel` | 说走就走 | 第一笔旅行基金 | 从空行李箱到出行装备齐备 |
| `gap` | 自由 Gap | 为阶段休整准备安全垫 | 从“不敢停”到“已批准” |
| `solo` | 攒一笔学习基金 | 为课程、考试、资料或技能学习准备预算 | 从确定方向到形成稳定的学习储蓄计划 |
| `custom` | 我的自定义目标（名称可修改） | 用户设置目标总额、默认每日金额 | 以 21 篇存钱日记记录计划与实际积累 |
| `retirement` | 给未来的自己 | 为自己存养老储备金 | 从未来来信到自己的养老花园 |

每条线包含 21 个旅程日，并以“觉醒、积累、守护”组织三个阶段。预设线有固定剧情，自定义线由用户填写计划与日记。七条线可以同时进行，顶部目标栏直接切换，不必先完成或退出其他线路。

学习基金线的第 1—7 天聚焦目标、费用和第一笔积累；第 8—14 天关注预算余地、稳定储蓄与成本比较；第 15—21 天关注培训防骗、合同留痕、支出能力和阶段复盘。为兼容旧存档，内部标识仍为 `solo`；原独居线的已完成天数、旅行和奖励记录继续保留，不重置用户进度。

### 自定义目标与多线并行

在“我的目标”选择页下方设置目标名称、目标总额、默认每日存钱金额和一句目标说明，再进入自定义卡片。进入后可以为每个旅程日单独填写“今天计划存”“实际记录”和日记；每天不必存相同金额。

- “保存计划与日记”只保存草稿，不增加金额、金币或完成天数。
- “确认记账并打卡”按用户填写的实际金额记一次账，不采用随机金额。实际记账金额须大于零；可小于当天计划，不强制达到计划才能打卡。
- 打卡后可修改计划和日记文字，实际已记金额只读，避免重复记账；日历中的“我的存钱日记”可回看每一天。
- 默认每日金额只用于尚未制定计划的日子，不覆盖已有日记。修改目标设置不删除已有记录。
- 目标金额进度与 21 天习惯进度分别计算。走完 21 天不代表已攒够目标金额；本版是一条固定的自定义线，暂不支持创建多个自定义副本或自动开启第二轮。

各线独立保存当前旅程日、已完成日、金额记录、存钱挑战、答题奖励、金币归属、AI 陪伴和旅行里程碑。旅程卡和结业页显示“本线金币”，选择页另显示总金币。账号的纪念品图鉴仍共用，金币不等于目标储蓄金额。AI 陪伴按“剧情线 + 旅程日 + 打卡快照”缓存，迟到的回答不会显示到另一条线；模型只接收打卡状态；自定义目标也不传名称、金额、日记或画像。

### 总体金额目标

七条线都可以在旅程卡的“总体金额目标”里填写目标金额，填写后立即显示“目标金额 / 已存多少 / 还需再存多少”，并给出完成比例和进度条。已存金额按该条线已记录的模拟金额自动累计，还需再存为目标金额减去已存金额，达成后显示“已经达成这个目标”。

- 目标按线独立保存在 `state.lineGoals`，切换目标时各自保留，自定义线的目标与选择页的“想攒到的金额”共用同一个值。
- 目标金额限定 0.01—1000000 元且最多两位小数，服务端 `PUT /api/state` 会校验格式。
- 主题线上的“清除”只删除金额目标，不删除已记录的金额；自定义线保持一个目标金额，可在同一处直接改。
- 目标金额只用于对照攒钱进度，不代表银行账户余额，也不参与金币或旅行奖励计算。

旧版未标记 `line` 的金额记录无法可靠分配到具体目标：原始记录继续保留，选择页标注为历史未分配金额，不复制到每条线或随意归属。新记录明确绑定目标。原来的单日挑战标记只迁移到已知归属线，旧版未保存的其他日期状态无法凭空恢复。

| 拼豆徽章 | 12 个多色拼豆图案，每个 10—38 颗豆子，合计 278 颗；完成一个任务点亮一颗豆子，填满一个图案得一枚徽章 |

| 行囊与结业 | 储蓄记录、纪念品图鉴、21 天打卡完成纪念页与工行官方内容入口 |
| 音乐与音效 | Web Audio 生成复古背景音乐及交互音效，支持静音 |

旅程页保留完整小屋卡片，下方以两列四宫格展示“今日玩法、今日存钱挑战、每日理财一问、AI 扑满陪伴”。四张卡片的内容直接可见，无需悬停展开；顶部设置栏支持横向滑动和功能跳转。小猪固定在页面右下角，允许少量遮挡内容。日历集中展示攒钱进度，小队进度位于小队页；整体采用深红、米白与暖金配色。

### 拼豆徽章规则

徽章页共有 12 个图案，难度从 10 颗豆子递增到 38 颗，合计 278 颗。每完成一个任务点亮一颗豆子：完成当天的剧情任务打卡 +1、完成今日存钱挑战 +1、答对每日理财一问 +1，七个目标的进度一起累计。豆子按“从上到下、从左到右”的顺序填进图案，填满一整个图案就得到对应徽章；未点亮的豆子显示为浅灰色，方便看出离完整图案还差多少。

豆子数量由已有存档推导（各线已完成天数、存钱挑战天数与答对题目数），不需要新增字段，双击 HTML 离线体验时同样可用。旧的按天数和纪念品数量解锁的规则已被替换；旅行纪念品仍单独在图鉴中收集。

### 21 天打卡完成页

当前目标第 1—21 天全部打卡后，自动进入打卡完成页；也可以通过旅程页的完成入口再次查看。仅浏览第 21 天、完成部分天数或存在重复记录不会触发完成。七条目标分别判断，完成一条不会结束其他目标；庆祝等待期间切换线路，不会被强制拉回。

页面以深红、米白和暖金呈现 21 天纪念章、扑满形象、21 个打卡印记、本目标的模拟记录金额和金币。设置了金额目标时，会说明是否达到金额，不把习惯打卡完成等同于攒够目标。回看不会重置记录或重复发奖。

“前往工行官方渠道，了解理财服务”在新窗口打开[工行官方个人手机银行介绍页](https://m.icbc.com.cn/column/1438058319981199366.html)，不直接唤起 App、不代办银行业务，也不在跳转链接中传递存钱金额、日记或用户标识。页面提供“回看我的 21 天”“继续其他目标”及音乐开关。后端仅记录本站的 `completion_explore_clicked` 点击事件，不将点击当作实际业务转化。

### 金币奖励与旅行规则

每日理财一问按“剧情线 + 旅程日”领取：答错不发金币，可阅读解析后重试；首次答对获得 1 金币，重复点击、刷新或重访该日不会再发奖。这里的“每日”是第 1—21 个旅程日，不是自然日。已经答对后，题目、选项和解析仍然展示。

每条剧情线完成 3、6、9、12、15、18、21 天任务时，各解锁一次旅行；同一用户的每条线同时最多一次旅行，不同线可以同时旅行。演示时长为 45 秒，回归后随机获得 3—10 金币及一件纪念品，优先选择尚未收集的纪念品。离开页面后计时仍按开始时间计算，下次打开并连接后端即可领取。后台线路返程不会重绘当前日记，奖励归到出发线路。已领取旅行不会再次发奖，同一线多次达标的旅行依次进行。

通过 Python 后端打开时，答案判断、旅行起止时间、随机奖励与领取记录由服务器管理，使用 SQLite 事务和唯一约束防止重复发放。后端异常时，答题显示重试提示，返程自动重试，不会直接补发本地奖励。双击 HTML 时使用独立的浏览器演示奖励，两种来源的奖励不合并；后端连接后以服务器记录为准。重启后端会自动创建新增数据表，不需要删除已有数据库。

总金币为原任务/存钱演示金币 `state.gold` 与新奖励账本金币 `rewards.gold` 之和；本线金币由 `lineGold` 及该线答题、旅行奖励计算。服务端发奖校验覆盖每日答题和旅行奖励；任务金币、任务完成进度和日记仍采用演示客户端存档，后端负责校验格式和持久化，匿名 ID 也不是正式身份认证，因此不能作为可兑换资产或生产级防作弊系统。旧版已完成答题没有服务端领取记录，可按新规则领取一次；清空数据库会清除领取记录。

## 4. 技术架构与数据流

前端使用原生 HTML、CSS、JavaScript，主页面内联样式和业务脚本，适配手机宽度。后端使用 Python 标准库 `ThreadingHTTPServer` 和 SQLite。本地和 Render 完整版本采用同源 API；GitHub Pages 主版本通过 `web/config.js` 指向 Render API，并由服务端校验来源、处理跨域预检。浏览器生成匿名演示用户 ID，通过 `X-User-ID` 请求头区分状态；该标识不属于生产级身份认证。Pages 与 Render 页面的浏览器存储属于不同来源，不会自动共享存档。

| 环节 | 处理方式 | 保存位置 |
| --- | --- | --- |
| 用户交互 | 更新页面状态，同时尝试同步服务端 | 浏览器 `localStorage`、`user_states` |
| 行为采集 | 记录任务、答题、挑战、存钱和旅程日切换 | `events` |
| 行为分析 | 按旅程日聚合特征，计算阶段概率与趋势 | `daily_behavior_features`、`behavior_states` |
| 财富画像 | 校验答案 → 服务端评分 → 组织题干与选项 → 模型或规则生成 | `ai_outputs`，以及前端同步的用户状态 |
| 陪伴建议 | 根据旅程、已完成任务和画像重点生成行动提示 | `ai_outputs`，以及前端同步的用户状态 |
| 答题与旅行奖励 | 服务端核验 → 事务内发奖 → 返回带版本的奖励快照 | `daily_quiz_answers`、`pet_trips`、`reward_ledger` |

数据库连接按请求提交或回滚并关闭。每个浏览器中的存档与匿名 ID 相互关联；不同浏览器或清除本地存储后，不会自动关联到原来的匿名账户。离线状态下仍可保存本地进度，但没有完整的离线事件队列与跨设备冲突解决机制。

多线存档沿用 `GET/PUT /api/state`，无需另建服务器。新增字段包括 `multiLineVersion: 1`、`lineDays`、`lineRecords`、`lineGold`、`challenges`、`aiCoaches` 与 `customLine`。前五类按固定线路 ID 分组，`aiCoaches[line][day]` 存每日建议，`customLine.entries[day]` 存 `target`、`amount`、`note`、`createdAt`、`completed`。后端拒绝未知线路、非法日期、非有限数、越界金额及超长日记；金额上限为 100 万元，最多两位小数，名称 30 字、目标说明 80 字、日记 240 字。

“同时进行”指同一存档中的多个目标独立推进，不等于多设备同时写入的冲突合并。当前仍采用整份 JSON 存档；多个浏览器标签或设备同时编辑同一匿名 ID 时，后保存者可能覆盖先前存档。答题和旅行账本独立于该 JSON，不会被普通存档覆盖。

## 5. DeepSeek 与财富画像

### 配置真实模型

分享包不含任何真实 API Key，也不携带原作者的私有配置。接收者需要自己的密钥；未配置时可以正常体验基础答题分析。

Windows 推荐使用隐藏输入配置工具：

```powershell
python web/private_config.py
```

在提示处粘贴密钥，输入不会回显。配置保存至 `%LOCALAPPDATA%\Puman21\deepseek.json`，由 Windows DPAPI 以当前用户范围加密；实际路径可能受 Windows 应用目录重定向影响，工具会显示保存位置。文件在项目目录外，拷贝或压缩源码目录不会带上它。更换电脑或 Windows 用户后，应重新配置。

默认接口为 `https://api.deepseek.com`，模型为 `deepseek-flash`。使用 JSON 输出，关闭思考模式，限制输出长度，默认等待上限为 40 秒。官方说明见 [DeepSeek API 文档](https://api-docs.deepseek.com/)。

配置或替换密钥后，先结束正在运行的旧服务，再执行：

```powershell
python web/server.py
```

访问 [AI 配置状态](http://127.0.0.1:8000/api/ai/status) 可查看 `configured` 与模型名；`configured: true` 仅表示配置齐全。已有基础画像可点击“更新画像”，只有调用成功且输出字段有效，页面才显示“AI 财富画像”。

其他操作系统或部署环境可以直接提供以下环境变量：

| 变量 | 用途 | 示例或默认值 |
| --- | --- | --- |
| `LLM_BASE_URL` | 兼容 Chat Completions 的服务地址 | `https://api.deepseek.com` |
| `LLM_API_KEY` | 后端鉴权密钥 | 由接收者通过秘密变量提供 |
| `LLM_MODEL` | 模型名称 | `deepseek-flash` |
| `LLM_TIMEOUT` | 请求等待秒数，代码限定为 1—60 秒 | 私有配置为 `40`，通用适配器缺省为 `15` |

显式环境变量优先于私有文件。`web/.env.example` 仅为配置参考，不含真实密钥；服务不会自动加载项目目录中的 `.env`。不要把实际密钥粘贴到 HTML、README、共享脚本或截图中。

后端部署还支持以下非秘密环境变量：

| 变量 | 用途 | 默认或配置方式 |
| --- | --- | --- |
| `HOST` | 监听地址 | 本地 `127.0.0.1`；Render 模板设为 `0.0.0.0` |
| `PORT` | HTTP 端口 | 本地 `8000`；云端采用 Render 分配值 |
| `DB_PATH` | SQLite 文件位置 | 本地 `web/puman.sqlite3`；云端按临时或持久磁盘配置 |
| `PUBLIC_ORIGIN` | 自定义后端域名来源 | 可选，例如 `https://api.example.com`，不含路径 |
| `RENDER_EXTERNAL_URL` | Render 后端公网来源 | 由 Render 自动提供，无需手动填写 |
| `ALLOWED_ORIGINS` | 可跨域调用 API 的前端来源 | 逗号分隔的完整来源；本项目为 `https://livreee.github.io`；不支持 `*` |

### 画像如何依据答案产生

四道题分别涉及生活愿望、工资分配习惯、向往的生活场景和额外收入用途，没有标准正确答案。浏览器提交四个选项下标，服务器根据固定题库重新计算剧情匹配计数，不采用客户端传入的 `line` 或 `scores`。

计数相同按 `home → baby → travel → gap → solo` 的顺序选择。该计数只表示剧情匹配，不代表资产状况、理财能力或风险承受能力。修改同一目标下的工资习惯或额外收入选择，也会改变相应的基础建议。

自定义线由用户主动设置，不参加偏好题自动推荐。学习基金版本把一道场景选项改为学习新技能，前后端题干及权重同步，画像版本为 `answers-v2-learning`。旧版本答案不会被强行套用到新题：需重新做偏好测试，已有旅程和金额记录不受影响。

服务器向模型发送题干、所选选项文字、计算后的匹配结果和参考分析。有效结果包含 `title`、`stage`、`focus`、`habit`、`message`；教育用途提示由服务器固定。页面展示四条答题依据，并支持重新测评、同答案缓存和手动更新。

| 返回来源 | 触发条件 | 页面表现 |
| --- | --- | --- |
| `provider: llm` | 模型请求成功且必要字段完整 | AI 财富画像 |
| `provider: rules` | 未配置、请求失败或模型输出无效 | 财富画像 · 答题分析 |
| 本地基础分析 | 直接打开 HTML 或后端不可用 | 标明本地答题分析，仍可继续旅程 |

`fallback_reason` 区分缺少配置与服务不可用。服务端审计中保存答案依据、输出、来源、模型名和时间；不保存密钥。重新答题后，旧请求迟到返回也不会覆盖新画像。AI 陪伴接口同样具有规则降级，但其结果不等于交易指令或投资建议。

## 6. 时序行为建模

`behavior_model.py` 实现无第三方依赖的 HMM-Lite 前向推断，模型版本为 `hmm-lite-v1`，输出启动期、尝试期、稳定期、波动期和回归期。

有效行为包括任务完成、每日答题、存钱挑战、储蓄记录、进入旅程日和选择剧情线；系统生成 AI 结果等事件不计入参与强度。每日聚合任务完成标志、答题次数与正确率、挑战完成、活动强度、连续完成天数和中断间隔，再通过固定状态转移矩阵和特征原型计算阶段概率。

未答题属于缺少证据，不按答错处理；空白旅程日会中断连续完成统计；补交旧日期事件时，重新计算后续已缓存日期。每日原始特征与每日状态摘要分别入库，前端“我的参与节奏”展示对应摘要。

当前版本按演示中的 `day=1…21` 聚合，不是按自然日自动计时；用户可以推进旅程日，因此“连续完成三天”表示连续三个旅程日有完成记录。主页面请求携带 `line`，后端只分析该用户该线事件，不把其他目标的打卡算进本线。分线视图按已存事件即时计算，不读取或覆盖原来的跨线缓存；省略 `line` 的旧接口继续返回账号聚合结果。旧事件没有线路标识时不纳入任何一条分线视图。正式研究或运营仍需明确自然日、时区和旅程轮次。

模型参数为人工设定的可解释先验，尚未用真实用户样本训练、校准或验证准确率。它用于参与节奏与习惯形成反馈，不用于信用、投资或金融风险判断。

## 7. API 与数据库

API 与页面同源，默认地址为 `http://127.0.0.1:8000`。用户接口需提供 `X-User-ID`（8—80 位字母、数字及 `_ . : -`）；健康检查与 AI 配置状态无需用户标识。JSON 请求使用 `Content-Type: application/json`。

| 方法 | 地址 | 作用 |
| --- | --- | --- |
| GET | `/api/health` | 服务健康状态 |
| GET | `/api/state` | 读取匿名用户存档及版本 |
| PUT | `/api/state` | 保存 `{"state": {...}}` |
| GET | `/api/rewards` | 读取金币、答题记录、旅行记录与当前旅行 |
| POST | `/api/daily-quiz/answer` | 提交 `{"line":"home","day":1,"selected":0}`，后端判题并发放首次答对奖励 |
| POST | `/api/travel/start` | 提交 `{"line":"home","milestone":3}`，核对已完成任务并开始旅行 |
| POST | `/api/travel/claim` | 提交 `{"trip_id":"出发接口返回的id"}`，核对返程时间并领取奖励 |
| POST | `/api/events` | 写入 `event_type` 和 `payload` |
| GET | `/api/metrics` | 当前用户各类事件计数 |
| GET | `/api/behavior/state?line=solo&day=3` | 指定线路截至该旅程日的状态摘要 |
| GET | `/api/behavior/timeline?line=custom&day=3` | 指定线路截至该旅程日的每日状态 |
| POST | `/api/behavior/recompute` | 以 `{"line":"solo","day":3}` 重新计算指定线路状态 |
| GET | `/api/ai/status` | 配置是否齐全及模型名称，不返回密钥 |
| POST | `/api/ai/profile` | 根据 `{"answers":[0,0,0,0]}` 生成画像 |
| POST | `/api/ai/coach` | 只接收 `day` 与 `completed_days`；派生打卡状态生成扑满话语，不接受自由对话 |

画像答案必须恰好四个，选项下标为整数 0—3。行为事件的 `payload.day` 必须为整数 1—21，每日答题的 `correct` 必须是布尔值。画像响应含 `profile`、`context`、`provider`、`model`、`fallback_reason` 和 `audit_id`。

新增奖励接口不接受客户端指定正确答案或发奖金额。每日题号按 `(day + 剧情线顺序) % 题库长度` 计算；剧情线顺序为 `home、baby、travel、gap、solo、custom`。成功响应包含权威 `rewards` 快照；存档 GET/PUT 同样返回该字段，PUT 会忽略客户端提交的 `state.rewards`。答题响应的 `awarded` 表示本次是否发奖；旅行未到时间返回 `pending: true` 与 `remaining_ms`，重复领取返回原金币和纪念品、`awarded: false`。`active_trips` 返回所有线路的进行中旅行，旧 `active_trip` 字段仅保留兼容。前端按快照 `revision` 丢弃过期响应。答题行为由新接口写入，无需再从前端上报同一答题事件。

重启新后端时，旅行表的旧“每用户一次活动旅行”索引会迁移为 `(user_id, line)` 的部分唯一索引，已有旅行和奖励不删除。不要删除数据库来应用本次更新。

| SQLite 表 | 内容 |
| --- | --- |
| `user_states` | 用户 JSON 状态、版本和更新时间 |
| `events` | 行为类型、内容和记录时间 |
| `ai_outputs` | 画像/陪伴请求、输出与来源审计 |
| `daily_behavior_features` | 每个用户每天的聚合特征 |
| `behavior_states` | 每个用户每天的阶段、概率、摘要与模型版本 |
| `daily_quiz_answers` | 每条剧情线每个旅程日的最新选项、答题结果与尝试次数 |
| `pet_trips` | 每次旅行的剧情线、里程碑、开始/返程/领取时间及奖励 |
| `reward_ledger` | 每笔新金币奖励及唯一领取键，独立于前端存档 |

数据库属于运行数据，不随分享包提供。接收者运行后会自行创建空数据库。后端只公开主 HTML、公开网址配置 `config.js` 和允许的静态资源；私有配置、Python 文件、SQLite 数据库及目录列表不可通过后端 HTTP 下载。API 默认同源，可为部署显式允许指定前端来源；模型请求不转发重定向中的鉴权头。GitHub 仓库及 Pages 中的源文件仍是公开的，因此秘密只放在项目外的本机私有配置或 Render 环境变量中。

## 8. 测试与常见问题

在项目根目录运行：

```powershell
python -m unittest discover -s web -p "test_*.py" -v
```

回归测试覆盖答题校验、规则与模型输出、模型异常降级、时序特征、缓存更新、用户隔离、DPAPI 加密、Git 外配置路径、HTTP 访问边界，以及 Render 域名与 Pages 跨域存档。奖励测试额外覆盖答错重试、并发答对/返程仅发一次、提前领取拒绝、随机金币上下限、存档伪造隔离、事务失败回滚与前后端每日题库答案一致性。测试使用临时数据库和虚构密钥，不调用付费模型；Windows 专属的加密测试在其他系统上跳过。

多目标测试覆盖分线日期/金额/日记的保存与恢复、非法金额拒绝、跨线记录拒绝、分线行为分析、七条线答题、同时旅行与旧索引无损迁移。页面联调另验证 320/390/1440 像素宽度、草稿不记账、修改日记不重复加钱、切线后 AI 迟到响应隔离、后台旅行不覆盖日记和旧存档迁移，以及拼豆豆子按任务累计、图案依次点亮与徽章发放。测试不会调用真实模型或改动线上环境。

| 现象 | 处理方式 |
| --- | --- |
| `python` 命令不可用 | 安装 Python 并加入 PATH；Windows 也可将命令中的 `python` 换成可用的 `py` |
| 8000 端口被占用 | 先结束旧的本项目服务；若是其他程序占用，设置环境变量 `PORT` 后按新端口访问，例如 PowerShell 先执行 `$env:PORT='8001'` |
| Pages 显示本地模式 | 检查 `web/config.js` 是否填写真实 Render HTTPS 地址、Pages 是否完成部署；再检查 Render 服务是否已唤醒 |
| 云端接口返回 403 | 检查 `ALLOWED_ORIGINS` 是否与页面来源一致；自定义后端域名还需配置 `PUBLIC_ORIGIN` |
| 只显示答题分析 | 检查 `/api/ai/status`；配置密钥后重启服务，再点击“更新画像” |
| 已配置但 AI 暂不可用 | 检查 DeepSeek 账户余额、密钥有效性和网络；页面会保留规则分析 |
| 双击 HTML 没有行为模型或 AI | 使用 `python web/server.py` 启动完整服务，不要用普通静态服务器代替 |
| 新奖励接口返回 404 或一直显示等待确认 | 重启本地 `python web/server.py` 加载新接口；本地修改不会自动更新 GitHub 或 Render |
| 更换电脑后私有配置不能解密 | 在新电脑上运行 `python web/private_config.py`，重新输入自己的密钥 |
| 受限沙箱中 DPAPI 测试失败 | 在正常 Windows 用户终端运行；不要改成把明文密钥写回源码 |
| 打开后没有声音 | 浏览器通常要求先点击页面；同时检查音乐开关和浏览器静音状态 |

## 10. 分享、打包与后续维护

运行以下命令可重新生成完整分享包：

```powershell
python tools/package_project.py
```

结果位于 `dist/`：一个带日期的 ZIP 和对应 `.sha256` 校验文件。ZIP 中只有一个项目顶层文件夹，包含本文、主版本、历史原型、素材、重构版计划书、完成页截图、测试和打包工具；`MANIFEST.sha256` 记录包内各文件的校验值。

打包工具采用指定目录与文件范围，排除私有配置、`.env`（保留 `.env.example`）、数据库、日志、缓存、Word 锁定文件、重复 ZIP 和 Git 历史；`tools/` 仅收录打包工具本身。打包前检查疑似模型密钥、GitHub/Render 令牌与私钥，并展开检查 Word 文档内容；命中时中止并仅报告文件名。根目录和 `web/` 的 `.gitignore` 为 Git 分享提供第二层排除保护。不要另外将 Windows 私有配置目录放入压缩包。

打包不会清空原项目的用户数据，也不会删除本机配置或历史 Git 仓库。接收者按本文启动即可使用空白演示环境；要使用真实 AI，需要配置自己的密钥。若密钥曾经进入其他公开文件或 Git 历史，应在供应商控制台撤销并更换，新增忽略规则不能清除已有历史。

继续开发时优先修改 `web/`；若调整财富问卷，需同步前端 `QUIZ` 与后端 `QUIZ_CONTENT`、`QUIZ_WEIGHTS`；若调整每日理财题库，需同步 `DAILY_QUIZ` 与 `rewards.py` 的 `QUIZ_ANSWERS` 并运行一致性测试。模型参数和画像版本变更时，应更新相应版本字段并运行测试。正式上线前还需要真实身份认证、服务端业务校验、支付/账户接口、真实小队数据、可靠的离线同步、运维监控与针对真实数据的模型评估。
